### ข้อที่ 2:
**คำถาม:** ตามหลักการ **"The 1-10-100 Rule"** ของการบริหารจัดการคุณภาพข้อมูลในธุรกิจ หากปล่อยให้ข้อมูลที่ผิดพลาดหลุดรอดไปจนถึงมือลูกค้า ธุรกิจจะต้องแบกรับต้นทุนความเสียหายอย่างไร?
- [x] A) เสียต้นทุนความเสียหายสูงสุด (100 เท่า) เช่น ลูกค้ากดยกเลิกสินค้า เสียชื่อเสียงแบรนด์ และสูญเสียงบโฆษณายิงแอดซ้ำซ้อน
- [ ] B) เสียต้นทุนเพียงเล็กน้อย (1 เท่า) เพราะสามารถส่งข้อความขอโทษลูกค้าในแชทได้โดยไม่มีค่าใช้จ่าย
- [ ] C) ไม่เสียต้นทุนใดๆ เลย เพราะระบบจะปรับปรุงตัวเลขในบัญชีให้ถูกต้องเองอัตโนมัติ
**เฉลย:** A) กฎ 1-10-100 ระบุว่า การป้องกันข้อมูลผิดแต่แรกใช้ต้นทุน 1 บาท, การคลีนข้อมูลก่อนวิเคราะห์ใช้ต้นทุน 10 บาท, แต่หากปล่อยให้ข้อมูลขยะหลุดไปถึงลูกค้า (เช่น ส่งของผิดบ้าน, ยิงโปรโมชันซ้ำ 3 รอบ, สต็อกขาดจนส่งไม่ทัน) ธุรกิจจะต้องจ่ายค่าแก้ไขและชดใช้ความเสียหายสูงถึง 100 บาท

### ข้อที่ 4:
**คำถาม:** ทำไม **"ช่องว่างล่องหน" (Hidden Whitespace)** เช่น การเผลอกด Spacebar ท้ายชื่อสินค้า `"ข้าวยำอกไก่ "` จึงถือเป็นฝันร้ายของการทำ Pivot Table และการค้นหาข้อมูลด้วย VLOOKUP?
- [x] A) เพราะคอมพิวเตอร์นับจำนวนตัวอักษรรวมช่องว่างด้วย ทำให้ระบบมองว่าเป็นคนละคำกับ `"ข้าวยำอกไก่"` ส่งผลให้ Pivot Table แยกเป็น 2 บรรทัดและรวมยอดขายไม่ได้
- [ ] B) เพราะโปรแกรม Google Sheets จะล็อกไฟล์และไม่อนุญาตให้แก้ไขข้อมูลจนกว่าจะลบช่องว่างออก
- [ ] C) เพราะช่องว่างจะทำให้ราคาสินค้ากลายเป็นค่าติดลบโดยอัตโนมัติ
**เฉลย:** A) สายตามนุษย์อาจมองไม่เห็นความต่าง แต่คอมพิวเตอร์มองว่า `"ข้าวยำอกไก่ "` (มี space ท้ายคำ) มีความยาวตัวอักษรมากกว่า `"ข้าวยำอกไก่"` ระบบจึงแยกเป็นสินค้าคนละชนิด ส่งผลให้การสรุปยอดขายด้วย Pivot Table หรือการค้นหาด้วย VLOOKUP แสดงผลลัพธ์เป็น #N/A วิธีแก้คือกด Trim whitespace หรือใช้ฟังก์ชัน `=TRIM()`

### ข้อที่ 5:
**คำถาม:** เจ้าของร้านแฟชั่นต้องการเปลี่ยนคำว่า `"White"` และ `"white"` ให้กลายเป็นคำภาษาไทยมาตรฐานคือ `"ขาว"` โดยใช้เครื่องมือ **Find & Replace (`Ctrl + H`)** เจ้าของร้านต้องติ๊กเลือกตัวเลือกใดเพื่อความปลอดภัยสูงสุดของข้อมูล?
- [ ] A) ติ๊กเลือก "Match case" เพื่อให้ค้นหาเฉพาะตัวพิมพ์ใหญ่เท่านั้น
- [ ] B) ติ๊กเลือก "Also search in formulas" เพื่อแก้สูตรคำนวณทั้งหมด
- [x] C) ติ๊กเลือก "Match entire cell contents" เพื่อป้องกันไม่ให้คำที่ค้นหาไปแทนที่ส่วนหนึ่งของคำอื่นโดยไม่ตั้งใจ
**เฉลย:** C) การติ๊ก "Match entire cell contents" เป็นกฎความปลอดภัยสำคัญของการใช้ Find & Replace เพราะจะแทนที่ก็ต่อเมื่อทั้งเซลล์มีข้อความตรงกับคำที่ค้นหา 100% เท่านั้น หากไม่ติ๊ก แล้วค้นหาคำว่า "ขาว" เพื่อแก้ข้อความ คำว่า "กางเกงขายาว" อาจถูกแทนที่จนกลายเป็น "กางเกงขาวยาว" สร้างความเสียหายให้กับฐานข้อมูล

### ข้อที่ 6:
**คำถาม:** เมื่อพบปัญหา **"ข้อมูลขาดหาย" (Missing Values / Null Data)** เช่น ช่องราคาสินค้าหรือเบอร์โทรศัพท์เว้นว่างไว้ ข้อใดอธิบายแนวทางการตัดสินใจเชิงธุรกิจได้อย่างถูกต้องที่สุด?
- [ ] A) ให้พิมพ์เลข 0 ลงในทุกช่องที่ว่างทันที เพื่อให้สูตรคณิตศาสตร์สามารถคำนวณต่อได้
- [x] B) พิจารณาว่าข้อมูลนั้นสำคัญต่อการวิเคราะห์หรือไม่ หากเป็นช่องสำคัญและมีไม่กี่แถวอาจลบทิ้ง (Deletion) แต่ถ้าเป็นช่องสำคัญที่ไม่ต้องการเสียข้อมูลแถวนั้นไป ให้แทนค่าด้วยค่ามาตรฐานที่สมเหตุสมผล (Imputation)
- [ ] C) ปล่อยช่องว่างไว้เช่นเดิม แล้วเพิ่มเครื่องหมายดอกจัน (*) กำกับไว้ทุกช่อง
**เฉลย:** B) การจัดการ Missing Data ต้องใช้ดุลยพินิจทางธุรกิจ การใส่เลข 0 มั่วซั่วจะทำให้ค่าเฉลี่ยทางสถิติเพี้ยนอย่างรุนแรง (เช่น ลูกค้าไม่ได้ซื้อ 0 บาท แต่ระบบลืมบันทึกยอดเงิน) แนวทางที่ถูกต้องคือ หากขาดข้อมูลวิกฤตอาจลบแถวทิ้ง (Delete) หรือถ้าต้องการรักษาแถวนั้นไว้ ให้เติมค่ามาตรฐาน (Impute) เช่น ดึงราคาจากแคตตาล็อก หรือระบุว่า "ไม่ระบุ"

### ข้อที่ 7:
**คำถาม:** ใน Google Sheets เทคนิคการตรวจสอบด้วยสายตา (Visual Inspection) ข้อใดที่ช่วยให้เราทราบได้ทันทีว่า **"คอลัมน์ตัวเลขหรือวันที่" กำลังมีปัญหาถูกระบบมองเป็นข้อความ (Text) ที่ไม่สามารถคำนวณได้?**
- [ ] A) เซลล์นั้นจะมีเส้นใต้สีแดงปรากฏขึ้นมาเตือน
- [x] B) ข้อมูลตัวเลขหรือวันที่ในเซลล์นั้นจัดวาง **"ชิดซ้าย" (Align Left)** แทนที่จะจัดวาง **"ชิดขวา" (Align Right)** ตามธรรมชาติของตัวเลข
- [ ] C) ขนาดตัวอักษรของเซลล์นั้นจะหดเล็กลงครึ่งหนึ่งโดยอัตโนมัติ
**เฉลย:** B) Alignment Rule เป็นกฎพื้นฐานของสเปรดชีต: ข้อมูลที่เป็นตัวเลข (Number) และวันที่ (Date) ที่แท้จริง ระบบจะจัดวางชิดขวา (Align Right) เสมอ หากเราเห็นตัวเลขหรือวันที่ถูกจัดวางชิดซ้าย (Align Left) แสดงว่ามีอักขระพิเศษ ช่องว่าง หรือสัญลักษณ์เงินแฝงอยู่ ทำให้ระบบมองเป็นข้อความ (Text) และสูตร SUM จะข้ามเซลล์นั้นไป

### ข้อที่ 8:
**คำถาม:** หากในตารางยอดขายมีรายการที่พนักงานคีย์จำนวนสินค้าผิดพลาดเป็น **999 ชิ้น** หรือคีย์ราคาผิดเป็น **-500 บาท (Outliers & Anomalies)** ค่าสุดโต่งนี้จะส่งผลกระทบต่อการตัดสินใจของธุรกิจอย่างไร?
- [x] A) จะดึงให้ค่าเฉลี่ย (Mean) สูงหรือต่ำกว่าความเป็นจริงอย่างมหาศาล ทำให้ฝ่ายจัดซื้อสต็อกสินค้าผิดพลาด และในกรณีที่มี Outlier ควรใช้ค่ามัธยฐาน (Median) ในการดูภาพรวมแทน
- [ ] B) จะทำให้ระบบลบชีตข้อมูลนั้นทิ้งเพื่อความปลอดภัยของฐานข้อมูล
- [ ] C) ไม่มีผลกระทบใดๆ เพราะสูตร AVERAGE จะตัดค่าที่มากเกินไปออกให้อัตโนมัติ
**เฉลย:** A) ค่าผิดปกติหลุดโลก (Outliers) มีอิทธิพลอย่างมากต่อ "ค่าเฉลี่ยเลขคณิต" (Mean) เช่น มีออเดอร์ 999 ชิ้นโผล่มาบิลเดียว ยอดสั่งซื้อเฉลี่ยจะพุ่งสูงจนฝ่ายบริหารเข้าใจผิดว่าร้านขายดีเป็นพันชิ้นและสั่งของมาดองจนเน่าทิ้ง ในทางสถิติจึงแนะนำให้สแกนหาค่า Min/Max ก่อนเสมอ และเลือกใช้ค่ามัธยฐาน (Median) ซึ่งทนทานต่อ Outlier มากกว่า

### ข้อที่ 9:

- [ ] A) ช่วยเพิ่มความเร็วในการดาวน์โหลดไฟล์ CSV จากอินเทอร์เน็ต
- [x] B) เป็นการป้องกันข้อผิดพลาดตั้งแต่ต้นทาง (Quality at the Source) เช่น ล็อกให้เลือกจาก Dropdown หรือล็อกช่วงตัวเลข และเลือก "Reject input" เพื่อไม่ให้ข้อมูลผิดพลาดถูกบันทึกลงชีตได้ตั้งแต่แรก

**เฉลย:** B) Data Validation เปรียบเสมือนด่านตรวจหน้าประตู หากเราสร้าง Dropdown ให้พนักงานเลือกไซส์เสื้อ (S, M, L) หรือล็อกช่วงจำนวนสินค้า (1-100 ชิ้น) พร้อมตั้งค่าปฏิเสธข้อมูลที่ผิด (Reject input) พนักงานจะไม่สามารถพิมพ์ผิดหรือเคาะเว้นวรรคได้เลย ช่วยตัดปัญหา Dirty Data ได้ 100% ตั้งแต่ต้นทาง
