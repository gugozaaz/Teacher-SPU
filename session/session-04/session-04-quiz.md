### ข้อที่ 1:
**คำถาม:** ข้อใดอธิบาย **"3 กฎเหล็กของ Tidy Data"** (คิดค้นโดย Hadley Wickham) ได้อย่างถูกต้องและครบถ้วนที่สุดสำหรับโครงสร้างตารางข้อมูลธุรกิจ?
- [ ] A) 1 แถว = 1 ยอดขายรวมทั้งเดือน, 1 คอลัมน์ = 1 สาขา, 1 ช่อง = สรุปผลกำไรสุทธิ
- [x] B) 1 แถว = 1 รายการสังเกต/ออเดอร์ (Observation), 1 คอลัมน์ = 1 ตัวแปร (Variable), 1 ช่อง = 1 ค่าเดียว (Single Value)
- [ ] C) 1 แถว = 1 วันทำการ, 1 คอลัมน์ = รายชื่อลูกค้าทุกคน, 1 ช่อง = รวมรายการสั่งซื้อทั้งหมดของวันนั้น
**เฉลย:** B) กฎเหล็ก 3 ข้อของ Tidy Data คือ 1) แต่ละแถวแทน 1 สิ่งที่สังเกตหรือ 1 ธุรกรรม (Observation) 2) แต่ละคอลัมน์แทน 1 ตัวแปรหรือคุณลักษณะ (Variable) เช่น วันที่, ชื่อสินค้า, ราคา และ 3) แต่ละช่องตารางมีเพียงค่าข้อมูลเดียว (Single Value / Atomic) เพื่อให้โปรแกรมและ AI สามารถประมวลผลได้ทันที

### ข้อที่ 2:
**คำถาม:** หากร้านค้าบันทึกออเดอร์โดยการเพิ่มคอลัมน์สินค้าไปทางขวาเรื่อยๆ เช่น `สินค้า_1`, `จำนวน_1`, `สินค้า_2`, `จำนวน_2`... โครงสร้างนี้ส่งผลเสียต่อการประมวลผลข้อมูลทางธุรกิจอย่างไร?
- [x] A) ตารางจะขยายออกด้านข้างไม่สิ้นสุด (Wide Data Sprawl) เกิดช่องว่าง (Null) จำนวนมาก และไม่สามารถใช้สูตรสรุปยอดรวมของสินค้าแต่ละชนิดได้โดยตรง
- [ ] B) ทำให้หน้าจอคอมพิวเตอร์ประมวลผลช้าลงจนเปิดไฟล์เอกสารไม่ได้
- [ ] C) ไม่มีผลเสียใดๆ เพราะโปรแกรม Excel แนะนำให้เก็บข้อมูลแนวนอนมากกว่าแนวตั้ง
**เฉลย:** A) การเพิ่มคอลัมน์สินค้าซ้ำซ้อนไปทางขวาทำให้โครงสร้างตารางไม่นิ่ง ขัดกับกฎ 1 คอลัมน์ = 1 ตัวแปร แนวทาง Tidy Data ที่ถูกต้องคือต้องบันทึก 1 รายการสินค้าที่สั่งซื้อ = 1 แถว (ขยายข้อมูลลงด้านล่าง) ทำให้คอลัมน์คงที่และคำนวณด้วย Pivot Table ได้ทันที

### ข้อที่ 3:
**คำถาม:** ทำไมการ **"ผสานเซลล์" (Merged Cells)** และการใส่ **"แถวยอดรวมย่อย" (Subtotals)** แทรกกลางตารางข้อมูล จึงเป็นข้อห้ามเด็ดขาดของ Data Science?
- [ ] A) เพราะโปรแกรม Google Sheets จะลบข้อมูลแถวนั้นทิ้งทันทีเมื่อกด Save
- [x] B) การผสานเซลล์ทำให้ค่าในเซลล์ล่างกลายเป็นค่าว่างเมื่อถูก Filter/Sort ส่วนแถวยอดรวมจะทำให้สูตร SUM คำนวณยอดเบิ้ลซ้ำซ้อน 2 เท่า
- [ ] C) เพราะทำให้ตัวหนังสือภาษาไทยเปลี่ยนเป็นภาษาต่างดาวทั้งหมด
**เฉลย:** B) การ Merge Cells ทำให้ระบบมองเห็นค่าเฉพาะเซลล์บนซ้าย เมื่อจัดเรียงหรือกรองข้อมูล แถวอื่นจะหลุดเป็นค่าว่าง (Null) ทันที และการใส่แถว Subtotal แทรกกลางข้อมูลดิบจะทำให้สูตรคำนวณผลรวมทั้งคอลัมน์บวกยอดซ้ำจนตัวเลขเพี้ยน 2 เท่า

### ข้อที่ 4:
**คำถาม:** เจ้าของร้านคาร์แคร์ใช้การ **"ไฮไลต์สีเขียว"** ในช่องตารางเพื่อบอกว่าลูกค้าชำระเงินแล้ว และ **"ไฮไลต์สีแดง"** เพื่อบอกว่าค้างชำระ วิธีการนี้มีข้อเสียอย่างไรและควรแก้ไขอย่างไรตามหลัก Tidy Data?
- [x] A) ฟังก์ชันสูตรและโมเดล AI มองไม่เห็นสีไฮไลต์ ทำให้กรองและวิเคราะห์ไม่ได้ ควรแก้โดยเพิ่มคอลัมน์ Payment_Status แล้วพิมพ์ข้อความ เช่น 'Paid' หรือ 'Pending'
- [ ] B) การใช้สีทำให้ไฟล์เปลืองพื้นที่หน่วยความจำมากเกินไป ควรเปลี่ยนมาใช้วิธีการขีดฆ่าข้อความแทน
- [ ] C) สีเขียวและสีแดงไม่แสดงผลบนมือถือ ควรเปลี่ยนมาพิมพ์ชื่อพนักงานแทน
**เฉลย:** A) กับดัก Color as Data คือการฝังความหมายของข้อมูลไว้ในสี ซึ่งสูตรคำนวณและ AI ไม่สามารถสแกนสีเซลล์มาคำนวณได้ การแก้ปัญหาที่ถูกต้องคือต้องเปลี่ยนสีให้กลายเป็นข้อมูลข้อความในคอลัมน์สถานะ (Text Column) เสมอ

### ข้อที่ 5:
**คำถาม:** ในตารางออเดอร์มีลูกค้าชื่อ **"คุณกิ๊ก"** สั่งซื้อเค้ก 2 ครั้ง (คนหนึ่งอยู่อารีย์ อีกคนอยู่ลาดพร้าว) หากตาราง **"ไม่มีรหัสกำกับเฉพาะ" (No Unique ID / Customer_ID)** จะส่งผลกระทบต่อธุรกิจอย่างไร?
- [ ] A) ไม่ส่งผลใดๆ เพราะพนักงานส่งของจำหน้าลูกค้าได้ทุกคน
- [x] B) ระบบและ AI จะเข้าใจผิดว่าเป็นลูกค้ารายเดียวกัน รวมยอดซื้อและประวัติการสั่งซื้อเข้าด้วยกัน ทำให้การวิเคราะห์พฤติกรรมลูกค้าและการตลาดเฉพาะบุคคล (Personalization) ผิดพลาดอย่างสิ้นเชิง
- [ ] C) เครื่องแม่ข่ายจะปฏิเสธการเชื่อมต่ออินเทอร์เน็ตทันที
**เฉลย:** B) กับดัก No Unique ID ทำให้เกิดปัญหาไม่สามารถแยกแยะสิ่งที่เหมือนกันได้ การมี Customer_ID และ Order_ID จะทำหน้าที่เป็น Primary Key ช่วยให้ระบบและ AI ระบุตัวตนลูกค้าแต่ละรายได้อย่างแม่นยำ 100% แม้ชื่อ-นามสกุลจะสะกดเหมือนกันก็ตาม

### ข้อที่ 6:
**คำถาม:** โครงสร้างข้อมูลแบบ **Long Format (ตารางแนวตั้ง / Tidy Data)** มีความสำคัญต่องาน Data Science และการใช้ AI มากกว่า **Wide Format (ตารางแนวนอน)** อย่างไร?
- [ ] A) Long Format มนุษย์สามารถกวาดสายตาอ่านสรุปยอดขายทั้งปีได้เร็วกว่า Wide Format
- [x] B) Long Format มีโครงสร้างคอลัมน์คงที่ ขยายข้อมูลลงด้านล่าง ทำให้คอมพิวเตอร์และ AI กรองข้อมูล จัดกลุ่ม และนำไปสร้าง Pivot Table วิเคราะห์ต่อได้ทันที
- [ ] C) Long Format รองรับเฉพาะข้อมูลตัวเลข ห้ามบันทึกตัวหนังสือ
**เฉลย:** B) Wide Format เหมาะสำหรับมนุษย์อ่านสรุปรายงาน (เช่น กาง 12 เดือนเป็น 12 คอลัมน์) แต่คอมพิวเตอร์และ AI วิเคราะห์ยาก ในทางกลับกัน Long Format (Tidy Data) เป็นโครงสร้างมาตรฐานที่ระบบประมวลผลและโมเดล AI นำไปวิเคราะห์ จัดกลุ่ม หรือแปลงกลับเป็น Pivot Table ได้อย่างสมบูรณ์แบบ

### ข้อที่ 7:
**คำถาม:** ในการสร้าง Google Forms หากเลือกคำถามประเภท **"Checkboxes (ช่องทำเครื่องหมาย - เลือกได้หลายข้อ)"** ให้ลูกค้าเลือกท็อปปิ้งเค้ก จะเกิดปัญหา Messy Data ใดขึ้นใน Google Sheets?
- [x] A) คำตอบที่ถูกเลือกทั้งหมดจะถูกยัดรวมกันเป็นข้อความเดียวคั่นด้วยลูกน้ำ (เช่น "ฝอยทอง, สตรอว์เบอร์รี, เม็ดมะม่วง") ในเซลล์เดียว ขัดกับกฎ 1 ช่อง = 1 ค่าเดียว
- [ ] B) ฟอร์มจะปฏิเสธไม่ให้ลูกค้ากดส่งคำตอบ
- [ ] C) ข้อมูลจะถูกแปลงเป็นรหัสภาษาต่างดาวและเปิดอ่านไม่ได้
**เฉลย:** A) กับดัก Checkbox ใน Google Forms จะนำค่าที่เลือกหลายข้อมารวมไว้ในเซลล์เดียวคั่นด้วยคอมม่า ทำให้สูตร COUNTIF หรือ Pivot Table ไม่สามารถนับจำนวนท็อปปิ้งแต่ละชนิดได้ วิธีแก้คือการแยกคำถามเป็นรายข้อ (เช่น ฝอยทอง: ใช่/ไม่ใช่) หรือสร้างแถวใหม่อย่างเป็นระเบียบ

### ข้อที่ 8:
**คำถาม:** เจ้าของร้านต้องการให้ลูกค้ากรอกข้อมูลผ่าน Google Forms โดยไม่ให้เกิดข้อมูลขยะ (Garbage Data) เช่น พิมพ์เบอร์โทรไม่ครบ หรือใส่จำนวนติดลบ ควรตั้งค่าฟอร์มอย่างไร?
- [ ] A) เปิดให้พิมพ์ในช่อง Paragraph และไม่ตั้งเงื่อนไขใดๆ เพื่อความสะดวกของลูกค้า
- [x] B) เปิดสวิตช์ Required ในทุกช่องที่จำเป็น และตั้งค่า Response Validation ล็อกเบอร์โทรศัพท์เป็นตัวเลข 10 หลัก และจำนวนสินค้าเป็นตัวเลขมากกว่า 0
- [ ] C) ส่งข้อความไปเตือนลูกค้าในไลน์เป็นรายคนหลังจากลูกค้ากรอกฟอร์มเสร็จแล้ว
**เฉลย:** B) หลักการ Quality at the Source คือการป้องกันข้อมูลเสียตั้งแต่ต้นทาง การเปิดสวิตช์ Required ป้องกันค่าว่าง (Missing Data) และการตั้งค่า Response Validation ตรวจสอบความถูกต้องของเบอร์โทรและตัวเลข ทำให้ข้อมูลที่ไหลลง Sheets สะอาดและพร้อมคำนวณทันที 100%

### ข้อที่ 9:
**คำถาม:** จากกรณีศึกษา **"ร้านปังปอนด์ โฮมเบเกอรี่"** และ **"ProClean Car Care"** การเปลี่ยนตารางข้อมูลเดิมที่ผิดพลาดมาเป็นโครงสร้าง **Tidy Data** ช่วยสร้างประโยชน์เชิงธุรกิจสูงสุดอย่างไร?
- [x] A) เปลี่ยนข้อมูลที่เคยคำนวณไม่ได้ ให้กลายเป็นตารางที่พร้อมนำไปทำ Pivot Table สรุปยอดขายล่วงหน้า วางแผนสต็อกวัตถุดิบเนย/น้ำยา และค้นพบพฤติกรรมลูกค้า (เช่น กลุ่มรถ SUV)
- [ ] B) ช่วยให้ทางร้านสามารถลดจำนวนพนักงานลงทั้งหมดและปิดร้านดำเนินงานผ่านออนไลน์อย่างเดียว
- [ ] C) ช่วยให้สินค้าของร้านขายได้ราคาสูงขึ้น 2 เท่าในทันที
**เฉลย:** A) ทั้งสองกรณีศึกษาแสดงให้เห็นว่า เมื่อเปลี่ยนจากตารางบันทึกในแชทหรือตารางที่ผสานเซลล์มั่ว มาเป็น Tidy Data ธุรกิจจะสามารถใช้ Pivot Table และ AI วิเคราะห์ข้อมูลเพื่อวางแผนสต็อกวัตถุดิบ ลดของเสีย และค้นพบกลุ่มลูกค้าที่ทำกำไรสูงสุดได้อย่างแม่นยำ

### ข้อที่ 10:
**คำถาม:** การจัดทำ **Data Dictionary (พจนานุกรมข้อมูล)** 5 องค์ประกอบ (Field Name, Description, Type, Allowed Values, Example) มีความสำคัญอย่างไรต่อการทำงานร่วมกับ AI?
- [ ] A) มีไว้สำหรับคำนวณตัวเลขทางคณิตศาสตร์แทนการใช้ฟังก์ชันในสเปรดชีต
- [x] B) เป็นคู่มือกลาง (Single Source of Truth) ที่ช่วยอธิบายความหมายและขอบเขตของข้อมูลอย่างชัดเจน เมื่อแนบให้ AI วิเคราะห์ AI จะเข้าใจบริบทถูกต้องและไม่คาดเดาข้อมูลผิดพลาด
- [ ] C) ใช้สำหรับแปลภาษาอังกฤษเป็นภาษาไทยในรายงานประจำปีเท่านั้น
**เฉลย:** B) Data Dictionary คือหัวใจของ Data Governance ช่วยให้พนักงานทุกคนเข้าใจตรงกันแม้มีคนลาออก และเมื่อนำไปแนบเป็น System Context ให้โมเดล AI (เช่น Gemini) AI จะเข้าใจความหมายเชิงลึกของแต่ละคอลัมน์ได้อย่างแม่นยำโดยไม่ตอบมั่ว (Hallucination)
