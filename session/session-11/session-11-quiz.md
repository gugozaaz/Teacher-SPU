### ข้อที่ 1:
**คำถาม:** ปัญหาคลาสสิกที่เรียกว่า **"The Last Mile Problem in Data Science"** ซึ่งทำให้โปรเจกต์วิเคราะห์ข้อมูลทางธุรกิจกว่า 80% ล้มเหลวและไม่สร้างผลลัพธ์จริง เกิดจากสาเหตุใด?
- [ ] A) เซิร์ฟเวอร์ของบริษัทมีหน่วยความจำไม่เพียงพอสำหรับการประมวลผลข้อมูลขนาดใหญ่
- [x] B) ทีมงานใช้เวลาส่วนใหญ่ไปกับการเตรียมและวิเคราะห์ข้อมูล แต่ล้มเหลวในการสื่อสารและโน้มน้าวให้ผู้บริหารเข้าใจจนนำไปสู่การตัดสินใจและการลงมือทำจริง (No Action Taken)
- [ ] C) ผู้บริหารบริษัทไม่สามารถอ่านภาษาอังกฤษในสูตร Spreadsheet ได้
**เฉลย:** B) (อ้างอิง Slide 4: THE LAST MILE PROBLEM IN DATA SCIENCE) The Last Mile Problem คือจุดตายของการทำ Data Science ในธุรกิจจริง แม้จะวิเคราะห์สถิติมาอย่างแม่นยำแค่ไหน แต่ถ้าตอนนำเสนอทำได้เพียงสาดตัวเลขดิบ (Data Dump) และไม่สามารถตอบได้ว่า "แล้วจะให้ทำอะไรต่อ?" ข้อมูลนั้นจะมีค่าเป็นศูนย์ทันทีเพราะไม่มีใครกล้าอนุมัติงบหรือนำไปปฏิบัติ

### ข้อที่ 2:
**คำถาม:** ข้อใดอธิบายความแตกต่างระหว่าง **"Data Reporting" (การรายงานข้อมูล)** กับ **"Data Storytelling" (การเล่าเรื่องด้วยข้อมูล)** ได้ถูกต้องที่สุด?
- [x] A) Data Reporting มุ่งบอกแค่ "เกิดอะไรขึ้นในอดีต" ด้วยตารางและสถิติครบถ้วน ขณะที่ Data Storytelling มุ่งตอบว่า "ทำไมจึงเกิด และเราควรทำอะไรต่อในอนาคต" เพื่อกระตุ้นการตัดสินใจ
- [ ] B) Data Reporting ใช้ตัวเลขภาษาไทย ส่วน Data Storytelling ต้องใช้ตัวเลขภาษาอังกฤษเท่านั้น
- [ ] C) Data Reporting เหมาะสำหรับเด็ก ส่วน Data Storytelling เหมาะสำหรับผู้สูงอายุ
**เฉลย:** A) (อ้างอิง Slide 5: DATA VS STORY) Data Reporting คือการรายงานอดีต (Passive) ที่มักทำให้ผู้ฟังสับสนและง่วงนอน ขณะที่ Data Storytelling มีเส้นเรื่อง (Narrative Arc) ที่เชื่อมโยงบริบท ความขัดแย้ง และทางออกในอนาคต ซึ่งกระตุ้นสมองส่วนอารมณ์และตรรกะจนนำไปสู่การลงมือทำจริง (Active Decision)

### ข้อที่ 3:
**คำถาม:** โครงสร้างหลัก 3 ส่วนของ **Data Story Framework** ที่ใช้ในการสื่อสารข้อมูลทางธุรกิจให้ทรงพลังประกอบด้วยขั้นตอนใดบ้างตามลำดับ?
- [ ] A) Plan → Do → Check
- [x] B) Context (บริบท/เดิมพัน) → Insight (สิ่งที่ค้นพบ & So What?) → Action (แผนปฏิบัติการ & คาดการณ์ ROI)
- [ ] C) Input → Process → Output
**เฉลย:** B) (อ้างอิง Slide 7: THE 3-PART DATA STORY FRAMEWORK) โครงสร้าง 3 ส่วน (C-I-A) คือเฟรมเวิร์กมาตรฐาน: 1. Context ตั้งฉากปัญหาและชี้เดิมพันที่ต้องแก้ 2. Insight เผยความจริงที่ซ่อนอยู่ในข้อมูลและอธิบายว่าทำไมจึงสำคัญ และ 3. Action เสนอแผนปฏิบัติการที่จับต้องได้พร้อมตัวเลขผลตอบแทนที่ชัดเจน

### ข้อที่ 4:
**คำถาม:** ในการเปิดเรื่องส่วน **Context (บริบท)** การระบุ **"The Stakes" (เดิมพันทางธุรกิจ)** เช่น *"หากเรายังฝืนยิงแอด 1 ล้านแบบเดิม เราจะขาดทุน 450,000 บาททันที"* ส่งผลต่อจิตวิทยาของผู้บริหารอย่างไร?
- [ ] A) ทำให้ผู้บริหารโกรธและไล่ผู้นำเสนอออกจากห้องทันที
- [x] B) ดึงดูดความสนใจได้ทันทีใน 30 วินาทีแรก เพราะมนุษย์มีสัญชาตญาณกลัวการสูญเสียมากกว่าอยากได้กำไร (Loss Aversion)
- [ ] C) ทำให้ผู้บริหารไม่เชื่อข้อมูลเพราะคิดว่าเป็นเรื่องโกหก
**เฉลย:** B) (อ้างอิง Slide 8: PILLAR 1: CONTEXT — SETTING THE STAKES) ตามหลักจิตวิทยาเศรษฐศาสตร์พฤติกรรม (Loss Aversion) ผู้บริหารจะตื่นตัวทันทีเมื่อรู้ว่า "เงินในกระเป๋าจะหายไปเท่าไรหากตัดสินใจผิด" การระบุเดิมพันให้ชัดเจนตั้งแต่เปิดเรื่องจะเปลี่ยนบรรยากาศห้องประชุมให้ทุกคนตั้งใจฟัง 100%

### ข้อที่ 5:
**คำถาม:** เทคนิค **"The 3x So What? Test"** ถูกนำมาใช้ในการนำเสนอข้อมูลเพื่อวัตถุประสงค์ใด?
- [ ] A) เพื่อถามซ้ำๆ กวนใจเพื่อนร่วมงานในห้องประชุม
- [x] B) เพื่อเค้นหาคุณค่าที่แท้จริง โดยเปลี่ยนจาก Data/Fact ธรรมดา ให้กลายเป็น "Actionable Insight" ที่ชี้นำกลยุทธ์ธุรกิจ
- [ ] C) เพื่อตรวจสอบว่าสูตรใน Google Sheets คำนวณถูกต้องหรือไม่
**เฉลย:** B) (อ้างอิง Slide 9: PILLAR 2: INSIGHT — THE "SO WHAT?" TEST) ข้อมูลดิบเช่น "ยอดขาย TikTok โต 85%" ยังไม่ใช่ Insight การถามว่า "แล้วยังไงต่อ? (So What?)" ซ้ำ 3 ครั้งจะช่วยขุดลึกลงไปจนพบว่า งบ Facebook เดิมกำลังสูญเปล่า และเราต้องตัดงบนั้นย้ายไปจ้าง Micro-KOL TikTok เพื่อชิงกำไรแทน

- [ ] A) ช่วยประหยัดพื้นที่บนหน้าจอได้มากกว่า

### ข้อที่ 7:
**คำถาม:** แนวคิด **Signal-to-Noise Ratio** และทฤษฎี Data-Ink Ratio ของ Edward Tufte แนะนำให้ผู้ทำสไลด์ข้อมูลปฏิบัติตัวอย่างไร?
- [ ] A) เพิ่มภาพการ์ตูนเคลื่อนไหว ดนตรีประกอบ และเอฟเฟกต์ 3 มิติให้ตื่นตาตื่นใจ
- [x] B) ตัดสิ่งรกสายตาที่ไม่จำเป็น (Visual Noise) เช่น เส้นตารางหนาเตอะ กรอบเงา 3D และตัวเลขทศนิยมยาวเหยียดทิ้งไป เพื่อขับให้สัญญาณข้อมูลเด่นชัด
- [ ] C) ใส่กราฟให้ครบทุกแบบทั้ง Bar, Line, Pie, และ Scatter ในสไลด์หน้าเดียวกัน
**เฉลย:** B) (อ้างอิง Slide 13: SLIDE DESIGN RULE 2: SIGNAL-TO-NOISE RATIO) กราฟที่ดีไม่ใช่กราฟที่มีลูกเล่นเยอะ แต่คือกราฟที่กำจัด "ขยะสายตา" ออกไปจนหมด เหลือไว้เฉพาะเนื้อข้อมูลสำคัญ (Data-Ink) ที่สื่อความหมายเท่านั้น ยิ่งขยะสายตาน้อย ผู้ฟังยิ่งเข้าใจประเด็นได้เร็วและไม่เหนื่อยล้า

### ข้อที่ 10:
**คำถาม:** การนำเสนอต่อผู้บริหารระดับสูงหรือนักลงทุนด้วยหลักการ **BLUF (Bottom-Line Up Front)** และสูตร **The 3-Minute Elevator Pitch** มีโครงสร้างการจัดสรรเวลาอย่างไร?
- [x] A) นาทีที่ 1: เปิดด้วย Hook, ชี้เดิมพัน และสรุปผลลัพธ์คำขอ (BLUF) → นาทีที่ 2: เจาะลึก Core Insight → นาทีที่ 3: แผนปฏิบัติการ คาดการณ์ ROI และขออนุมัติงบ (The Ask)
- [ ] B) นาทีที่ 1 ถึง 2 เล่าประวัติผู้ก่อตั้ง และนาทีที่ 3 เล่าสูตรคณิตศาสตร์
- [ ] C) พูดไปเรื่อยๆ จนกว่ากรรมการจะสั่งให้หยุดพูด
**เฉลย:** A) (อ้างอิง Slide 18: BLUF PRINCIPLE & Slide 19: THE 3-MINUTE ELEVATOR PITCH) หลักการ BLUF กำหนดให้วางบทสรุปและคำขอไว้ตั้งแต่ 1 นาทีแรก เพื่อให้ผู้บริหารได้รับสาระสำคัญทันที จากนั้นนาทีที่ 2 ใช้สนับสนุนด้วย Insight และนาทีที่ 3 ปิดด้วย Action Plan และ The Clear Ask ขออนุมัติงบ ซึ่งเหมาะเจาะกับเวลา 180 วินาที
